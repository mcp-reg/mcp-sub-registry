# Codebase Structure

**Analysis Date:** 2026-02-18

## Directory Layout

```

│   │   ├── components/     # Reusable React components
```

## Directory Purposes

**`internal/handler/`:**
- Purpose: HTTP request handling, routing, response serialization
- Contains: Endpoint handlers, parameter extraction, error-to-HTTP mapping
- Key files:
  - `router.go`: Chi router setup with middleware (CORS, logging, recovery)
  - `handler.go`: Base handler struct, JSON utilities, error handling
  - `servers.go`: List servers endpoint (with search/pagination)
  - `versions.go`: Server version endpoints (latest, specific, list all)
  - `refresh.go`: Cache invalidation endpoint
  - `health.go`: Health check endpoint
  - `handler_test.go`: Unit tests for handlers

**`internal/service/`:**
- Purpose: Business logic, aggregation, transformation, external service integration
- Contains: Registry fetching, filtering, pagination, GitHub API client, data transformation
- Key files:
  - `registry.go`: Main registry service (FetchRegistry, QueryServers, filtering/pagination logic)
  - `github.go`: GitHub Contents API client with error handling
  - `transformer.go`: Data transformation for different registry sources (VSCode, Obot, generic)
  - `http_client.go`: Reusable HTTP client with timeout configuration
  - Service tests: `registry_test.go`, `github_test.go`, `transformer_test.go`, `github_integration_test.go`

**`internal/model/`:**
- Purpose: Domain models and data transfer objects
- Contains: Type definitions for servers, responses, requests, registries
- Key files:
  - `server.go`: Server, Package, Icon, Repository, Remote structures
  - `response.go`: ServerWrapper, ServerListResponse, ErrorResponse, HealthResponse
  - `request.go`: RepoRef (org/repo/branch identifier), ListParams (pagination/search)
  - `registry.go`: RegistryFile, RegistryEntry (registry.json structure)
  - `model_test.go`: Tests for model logic

**`internal/cache/`:**
- Purpose: Multi-tier caching to reduce GitHub API load
- Contains: Cache manager, filesystem store, TTL handling
- Key files:
  - `cache.go`: Manager wrapper around gocache with Get/Set/Delete/GetWithTTL
  - `filesystem_store.go`: Custom store for persisting cache to filesystem

**`internal/config/`:**
- Purpose: Environment-based configuration
- Contains: Environment variable loading, defaults
- Key files:
  - `config.go`: Config struct, Load() function reading PORT, GITHUB_TOKEN, CACHE_TTL, CACHE_BASE_DIR, CACHE_ENABLED, BROWSER_CACHE_TTL

**`internal/validator/`:**
- Purpose: JSON schema validation for server.json files
- Contains: Schema loading, validation logic
- Key files:
  - `validator.go`: Validator struct with embedded schema, ValidateServer() method
  - `schemas/server.schema.json`: JSON Schema for validating server definitions
  - `validator_test.go`: Schema validation tests

**`internal/version/`:**
- Purpose: Version information tracking
- Contains: Version constants and build info
- Key files: `version.go`

**`internal/frontend/`:**
- Purpose: Serve embedded React SPA
- Contains: Frontend embedding logic with SPA fallback for client-side routing
- Key files:
  - `embed.go`: Handler that serves `dist/` directory, returns index.html for unknown routes
  - `embed_stub.go`: Stub when not built with `-tags=embed`

**`web/src/pages/`:**
- Purpose: Full-page route components
- Key files:
  - `SetupJourney.tsx`: Landing page (/) — GitHub URL input, example links
  - `OrgRepoPage.tsx`: Registry view (/:org/:repo) — displays servers, refresh button, copy API URL
  - `ServerDetailPage.tsx`: Server detail page (/:org/:repo/:serverName) — full server info
  - `RepoNotFound.tsx`: Error page when registry.json missing
  - `Registry.tsx`: Shared registry display component with server cards, search, metadata

**`web/src/components/`:**
- Purpose: Reusable React components
- Key files:
  - `ServerCard.tsx`: Card component for single server in list
  - `Header.tsx`: Top navigation with logo, links
  - `Footer.tsx`: Footer with copyright/links
  - `CopyButton.tsx`: Button that copies to clipboard with feedback
  - `Logo.tsx`: Logo component
  - `ui/`: shadcn-style UI primitives (card, button, input)

**`web/src/api/`:**
- Purpose: API client functions
- Key files:
  - `registry.ts`: Fetch functions (fetchServers, fetchServerDetails, refreshCache) with error handling

**`web/src/lib/`:**
- Purpose: Utility functions
- Key files: `utils.ts` (CSS class utilities, etc.)

**`web/src/types/`:**
- Purpose: TypeScript type definitions matching backend models
- Key files:
  - `server.ts`: Icon, GithubInfo, Repository, Server, ServerWrapper, ServersResponse, ErrorResponse, VersionResponse

**`testdata/`:**
- Purpose: Test fixtures and example data
- Contains:
  - `fixtures/valid/`: Valid registry.json and server.json examples
  - `fixtures/invalid/`: Invalid examples for error case testing

**`bin/`:**
- Purpose: Build outputs
- Contains: Compiled binaries (empty in source, populated by build)

**`scripts/`:**
- Purpose: Build and release automation
- Contains: Cross-platform build scripts

## Key File Locations

**Entry Points:**
- `main.go`: Go backend entry point — loads config, initializes services, starts HTTP server on port 8080
- `web/src/main.tsx`: React frontend entry point — mounts App component in #root
- `web/src/App.tsx`: Frontend router definition

**Configuration:**
- `internal/config/config.go`: Environment variable loading (PORT, GITHUB_TOKEN, CACHE_*, BROWSER_CACHE_TTL)
- `Makefile`: Development commands (make dev, make run, make web-dev, make test)
- `web/vite.config.ts`: Frontend build configuration
- `web/tsconfig.json`: TypeScript compiler options

**Core Logic:**
- `internal/service/registry.go`: Main registry aggregation and transformation logic
- `internal/service/github.go`: GitHub API client
- `internal/service/transformer.go`: Data normalization for different registry sources
- `internal/handler/router.go`: HTTP route definitions and middleware

**Testing:**
- `internal/handler/handler_test.go`: Handler tests
- `internal/service/registry_test.go`: Registry service tests
- `internal/service/github_test.go`: GitHub client tests
- `internal/service/transformer_test.go`: Transformer tests
- `internal/validator/validator_test.go`: Schema validation tests
- `internal/model/model_test.go`: Model tests
- `e2e_test.go`: End-to-end tests (requires -tags=e2e)

## Naming Conventions

**Files:**
- Go source: `lowercase_with_underscores.go` (e.g., `github.go`, `registry.go`)
- Go tests: `{component}_test.go` matching source file (e.g., `registry_test.go`)
- React components: PascalCase with `.tsx` extension (e.g., `ServerCard.tsx`, `SetupJourney.tsx`)
- Type definitions: PascalCase interfaces/types matching naming (e.g., `ServerWrapper`, `ErrorResponse`)
- Utility/helper modules: camelCase (e.g., `registry.ts`, `utils.ts`)

**Directories:**
- Internal packages: lowercase (e.g., `handler`, `service`, `cache`)
- React directories: lowercase (e.g., `pages`, `components`, `api`)
- Sub-directories: descriptive lowercase (e.g., `ui/` for UI components, `schemas/` for JSON schemas)

**Constants/Types:**
- Go: PascalCase for exported, camelCase for unexported (e.g., `DefaultLimit`, `MaxLimit`)
- TypeScript: PascalCase for types/interfaces, UPPER_SNAKE_CASE for constants (e.g., `API_BASE`)

**Functions:**
- Go: PascalCase for exported, camelCase for unexported (e.g., `NewRegistryService`, `extractRepoRef`)
- TypeScript: camelCase (e.g., `fetchServers`, `refreshCache`, `parseGitHubUrl`)

## Where to Add New Code

**New Backend Endpoint:**
1. Add handler method to `internal/handler/{feature}.go`
2. Register route in `internal/handler/router.go`
3. Add business logic to `internal/service/registry.go` or new service file
4. Define request/response models in `internal/model/{feature}.go`
5. Add tests: `internal/handler/{feature}_test.go` and service tests

**New Frontend Page:**
1. Create component in `web/src/pages/{FeatureName}.tsx`
2. Add route in `web/src/App.tsx`
3. Add new types to `web/src/types/server.ts` if needed
4. Add API client functions to `web/src/api/registry.ts` if calling backend

**New Frontend Component:**
1. Create reusable component in `web/src/components/{ComponentName}.tsx`
2. Import and use in page components or other components
3. For UI primitives, use/extend `web/src/components/ui/` shadcn components

**New Validator/Transformation:**
1. Update schema in `internal/validator/schemas/server.schema.json` if needed
2. Add transformation logic to `internal/service/transformer.go`
3. Add test fixtures to `testdata/fixtures/` if needed

**Utilities/Helpers:**
- Go: Add unexported helper functions in relevant package files (e.g., internal helpers in `handler.go`, `registry.go`)
- TypeScript: Add to `web/src/lib/utils.ts` or create feature-specific utility file

## Special Directories

**`internal/frontend/dist/`:**
- Purpose: Embedded React SPA build output
- Generated: Yes (by `make web-build` or Vite)
- Committed: No (in .gitignore, regenerated on build)
- Contains: Hashed asset files from Vite bundling
- Embedding: Embedded as `//go:embed all:dist` in `embed.go` when built with `-tags=embed`

**`testdata/`:**
- Purpose: Test fixtures and example data
- Generated: No
- Committed: Yes
- Contains: Valid/invalid registry and server JSON examples for testing

**`web/node_modules/`:**
- Purpose: Frontend dependencies
- Generated: Yes (by npm install)
- Committed: No (in .gitignore)

**`bin/`:**
- Purpose: Build outputs
- Generated: Yes (populated by make targets)
- Committed: No
